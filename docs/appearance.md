# 하루서랍 읽기 화면과 테마

앱·저장 보고서·원본 내용 정리의 상단 선택에서 시스템, 라이트, 다크를 고른다. 라이트는 종이색,
다크는 차콜색이며, 갈색 계열 강조색을 작은 이동·선택 표시에 사용한다. 요약은 종이 패널,
긴 본문은 제한한 읽기 폭과 문단 여백을 사용하고 좁은 화면의 제목은 균형 있게 줄바꿈한다.

[Bear의 테마](https://bear.app/faq/about-free-and-pro-themes-in-bear/)와
[글자 설정](https://bear.app/faq/typography-options/),
[Instapaper의 읽기 화면](https://www.instapaper.com/iphone)을 참고했다.

## 선택과 저장

- 선택은 해당 브라우저의 `localStorage["haru.theme"]`에 저장한다. 앱·HTML이 같은 출처에서 열리면
  다른 탭에도 반영한다. 폰과 노트북은 각각 자신의 읽기 화면을 선택한다.
- 시스템 모드는 `prefers-color-scheme` 변경을 따라간다. 명시적으로 고른 라이트·다크는 유지한다.
- 첫 화면이 나오기 전에 테마를 적용한다. 저장 공간 접근이 막힌 환경에서도 현재 화면 전환은 동작한다.
- 직접 파일로 연 HTML의 선택 유지·파일 간 공유는 브라우저의 파일 출처 저장 정책에 따라 다르다.
- 인쇄용 스타일은 읽기 모드와 관계없이 흰 바탕이다. 잠금 카드 PNG는 기존 카드 설정을 사용한다.

## 공통 구현

`app/css/theme.css`와 `app/js/theme.js`를 공유한다. 저장 HTML은 CSS와 테마 스크립트를 자체 포함하며
외부 폰트·스크립트 요청이 필요 없다. `haru/appearance.py`가 정확한 스크립트의 SHA-256을 계산해
저장 문서의 CSP에 넣는다. `default-src 'none'`, `base-uri 'none'`, `form-action 'none'`을 유지하고,
자료에 들어 있는 스크립트는 계속 이스케이프한다. 문서의 내용이나 분석 버전은 바꾸지 않는다.

## 검증

```sh
python -m pytest -q tests
node --test test/theme.test.mjs
node --check app/js/theme.js
```

Python 75개와 테마 동작 4개를 통과했다. 저장 문서의 정확한 CSP 해시와 자료의 코드 차단,
초기 선택·재로드·시스템 변경·탭 간 반영·저장 공간 실패를 검증한다. 최종 읽기 스타일 변경 후
보고서·브리핑·CSP 관련 20개도 재확인했다.

CUA 인앱브라우저로 앱과 저장 문서의 두 모드, 1280×720·742×853·390×844·320×780,
768×900 경계 화면을 확인했다. 가로 넘침, 콘솔 오류·경고가 없다. 실제 기기의 모드를 바꾸는
OS 검사는 하지 않았고 시스템 전환은 모의 이벤트 테스트로 확인했다. 인앱브라우저가 `file:` 주소를
허용하지 않아 직접 파일 열기의 시각 검사는 수행하지 않았다. 동일 HTML을 로컬 HTTP로 열고
자체 포함 구조를 검사했다.

이 변경은 현재 소스와 로컬 웹 화면에 적용했다. 기존 v0.1.3 APK에는 포함되지 않으며,
새 APK·CI와 실제 폰 화면 검증은 별도로 진행해야 한다. 개인 화면과 보고서는 저장소에 포함하지 않는다.
