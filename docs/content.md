# 보고서에서 블로그 초안과 대표 이미지로

완성한 YouTube 원본 정리에서 일관된 주제 하나를 골라 정보형 블로그 초안 한 편을 만든다. 이미지 생성은 Codex 채팅의 내장 ImageGen 도구가 맡으며, Python 앱은 생성된 이미지를 확인하고 파일에 연결한다. 블로그 서비스로 발행하는 기능은 없다.

## 설정과 입력

`content.enabled`의 기본값은 false다. 전용 환경에서 활성화하면 앱 보고서의 파일 도구 아래에 **블로그 초안 → 초안 읽기**가 나타난다. `content.start_day`를 지정하면 그 날짜 이후의 보고서와 이미 시작한 미완료 작업만 예약 대상으로 조회한다. 예전 날짜를 직접 `build`하는 것은 가능하다.

AI가 실제 분석한 보고서에서 분석 완료·전체 원본 정리 완료 상태인 공개 YouTube 링크만 사용한다. 영상 제목·채널·URL·원본 순서 정리·미확인 사항을 입력하며 개인 메모·할 일·사용자 프로필·계정·저장 목록·카카오톡·갤러리 자료는 입력하지 않는다. 제목·설명만 있는 영상과 규칙/예시 보고서로는 초안을 만들지 않는다.

글은 4~7개 소제목과 충분한 본문, 공개 출처, 발행 전 확인할 메모를 포함한다. 직접 체험한 후기나 투자·여행 경험을 꾸미지 않고 긴 원문 인용을 피한다. 이미지 프롬프트는 글 주제를 설명하는 새 일러스트로 구성한다.

## 실행

항상 해당 데이터의 `HARU_HOME`과 `HARU_INBOX`를 명시하고 프로젝트 폴더에서 실행한다.

```sh
python -m haru content status
python -m haru content build --day YYYY-MM-DD
python -m haru content attach-image --day YYYY-MM-DD --signature 'build의 signature' --file '/생성한/이미지.png'
python -m haru content status --day YYYY-MM-DD
```

1. `status`의 `pending`을 확인한다. 변화도 남은 작업도 없으면 글쓰기·이미지 AI를 호출하지 않는다.
2. `build`는 HTML·Markdown 글과 `image_prompt`를 저장한다. `status:image_pending`은 글만 완료된 상태다.
3. 내장 ImageGen으로 반환된 프롬프트의 대표 이미지 한 장을 생성한다. 별도 이미지 API 키·과금 경로로 자동 전환하지 않는다.
4. 생성된 실제 파일을 `attach-image`에 전달한다. 최소 512px의 PNG·JPEG·WebP 파일을 검사한 뒤 바이트 그대로 날짜 폴더에 복사한다. 다른 보고서 버전의 이미지는 거절한다.
5. 마지막 `ready:true`를 확인한다. 이미지 실패·파일 유실·자료 변경은 남은 작업으로 유지한다. 예약의 `youtube done --day YYYY-MM-DD`는 수집·보고서·대상 콘텐츠가 모두 완료된 뒤 기록한다. 날짜에는 최초 `youtube due`가 반환한 `day`를 사용한다. 긴 작업이 자정을 넘겨 끝나도 다음 날의 예약을 건너뛰지 않도록 수집 날짜를 유지한다. `--day` 없이 실행하면 기존처럼 현재 한국 날짜를 기록한다.

브라우저 예약의 한국 실행 시각은 `youtube.report_hour`로 지정한다(0~23, 기본 22). 자정 실행은 0이다. 기본 새벽 4시 날짜 경계에 따라 자정 직후 발견한 영상은 직전 날의 보고서에 모인다. 완료 기록의 날짜는 보고서 날짜와 구분하여 최초 due가 반환한 실행 날짜를 사용한다.

같은 자료를 다시 실행하면 저장한 글과 이미지를 재사용한다. 완성한 글 파일은 다시 쓰지 않아 직접 수정한 내용을 보존한다. 파일이 유실된 경우에만 저장한 생성 초안으로 누락 파일을 복구한다. 보고서 자료가 바뀌면 새 버전을 만들고 이전 결과도 보관한다. 글 수정 후 대표 이미지를 새로 연결하면 저장한 생성 초안으로 HTML·Markdown이 다시 만들어지므로 변경 전 별도 사본을 남긴다.

## 파일과 화면

보관 위치는 보고서의 `날짜/콘텐츠/v보고서버전-자료해시/`다.

- `blog.html`: 자체 포함 CSS·시스템/라이트/다크 선택·출처·대표 이미지
- `blog.md`: 편집하거나 옮길 글
- `cover-이미지해시.png/jpg/webp`: 생성된 대표 이미지 원본
- `draft.json`, `image-prompt.txt`, `.content-index.json`: 작업 재개용 내부 자료

로컬 서버는 목록에 등록한 HTML·Markdown·대표 이미지만 제공한다. 내부 JSON·프롬프트·작업 목록은 웹 주소로 열 수 없다. 기존 보고서의 파일 목록과 별도로 관리하여 보고서를 내보내도 콘텐츠 파일을 지우지 않는다. 자료 속 HTML은 화면에서 이스케이프하며 테마의 고정 스크립트만 CSP 해시로 허용한다.

현재 앱의 콘텐츠 링크는 노트북 웹 화면에 있다. 폰으로 보내는 암호화된 보고서·잠금 카드는 기존 기능이며 블로그 초안·이미지의 폰 전송은 이번 연결에 포함하지 않는다. 공개 Git에 개인 보고서·콘텐츠·계정·스냅샷을 넣지 않는다.
