# 읽기 중심 UI

## 후속: 부드러운 하루 기록 화면 (2026-10-03)

딱딱한 문서 느낌을 줄여 달라는 요청에 따라 기존 화면과 파일 보고서를 함께 다듬었다. 새 앱을 만들거나 분석 내용을 다시 생성하지 않았다.

- 밝은 화면은 종이색 `#faf8f2`, 잉크색 `#29382f`, 차분한 녹색 `#42634b`, 요약 영역 `#e9efdf`를 쓴다. 제목의 두께를 줄이고 작은 안내 문구와 여백으로 위계를 만든다. 탐색 선택은 연한 배경, 정리 버튼은 작은 테두리 버튼이다.
- 3줄 요약 → 상세 브리핑 → 원본 내용 정리 구조를 유지한다. ‘자료별로 읽기’와 ‘눈여겨볼 이야기’ 버튼은 실제 위치로 이동하고 키보드 초점도 옮긴다.
- 영상의 채널·길이·목록은 제목 아래, 처음 발견한 날짜와 전체 분석 안내는 ‘수집·분석 정보’에 보존한다. 원본 정리는 정리본임을 설명하며 수치·이름의 불확실성은 내용에서 유지한다.
- 앱의 시간순 원본에는 구간 목차를 추가했다. 저장 원본 HTML에는 영상 목차, 영상별 시간 목차와 상단의 브리핑/목차 이동을 넣었다. JavaScript나 외부 폰트 없이 파일로도 읽는다.
- `haru/reading_style.py`가 두 저장 HTML의 스타일을 공유한다. 보고서 JSON·Markdown·TXT/SRT, 데이터 구조와 폰 전송 형식은 바꾸지 않았다. 웹·Capacitor 공유 소스에 반영했으며 새 APK는 빌드하지 않았다.

검증: 전체 Python **73개 통과**, JS 구문과 Git 공백 검사 통과. CUA 인앱브라우저 1440×900·390×844에서 앱·저장 보고서·원본 자료를 검사했다. 분류, 펼치기, 목차 링크, Enter로 구간 이동/초점 전달을 확인했다. 가로 넘침과 콘솔 오류/경고가 없다. 실제 보고서의 84개 원본 소주제, 내용 파일 11개가 보존되고 파일·앵커 링크 115개가 유효하다. 어두운 색상 토큰은 조정했지만 이번 화면 검사는 밝은 테마다. 실제 폰 수신·잠금화면은 미검증이다.

참고: [Day One의 탐색 개선](https://dayoneapp.com/blog/new-navigation-layout-2024-11/)과 [Things](https://culturedcode.com/things/index.html). 단순한 탐색과 여백을 참고하되 하루서랍의 문구와 색으로 구현했다.

## 초기 개편

Readwise Reader의 탐색·읽기 영역 구분과 Things의 목록·여백을 참고해 기존 웹·Capacitor 공유 화면을 개편했다. 원본 서비스를 복제한 디자인은 아니다.

- 데스크톱은 왼쪽 메뉴, 보고서 본문, 잠금화면·파일 보관 도구로 나눈다. 모바일은 다섯 하단 메뉴를 쓰고 도구를 본문 뒤에 둔다.
- 보고서의 핵심·할 일·자료를 먼저 읽는다. 분류 버튼은 실제 자료 목록을 필터링한다. 핵심/관련 자료 이동은 필터를 해제하고 원본으로 이동한다.
- A/B 선택은 열린 미리보기와 스크롤을 유지한다. 선택은 저장하며, Android에서는 기존 네이티브 설정 API도 사용한다.
- 할 일 체크와 관련 자료 링크를 별도 컨트롤로 구분했다. 입력에 label을 연결하고, 확대 이미지는 Escape로 닫은 뒤 원래 버튼에 초점을 돌린다.
- 유튜브는 실제 서버 상태·수치를 표로 보여준다. 첫 수집의 비교 기준, 처음 발견한 날짜, 자막 범위, 실행 조건은 설명에 남긴다. 브라우저 수집과 OAuth 입력·연결 동작은 기존 API를 쓴다.
- 초기 저장용 HTML은 흰 본문과 구분선 중심이었다. 후속 개편은 위의 종이색과 녹색을 적용하며 독립 파일로 열 수 있는 구조와 기존 CSP를 유지한다.

Lucide 공식 SVG를 로컬에 포함했다. 출처와 라이선스는 `app/vendor/README.md`, `LUCIDE-LICENSE`에 있다. 기존 Pretendard와 어두운 화면, 안전 영역, 동작 줄이기 설정을 유지한다.

## 검증

2026-10-03 로컬 검증: Python 47개 통과. HTML 스타일 변경 후 파일 보관 테스트 6개 재확인. 네 JS 모듈의 `node --check`와 `git diff --check` 통과.

Codex 인앱브라우저에서 보고서 1496×1051·1280×720, 유튜브 1280×900, 모바일 390×844·360×780을 확인했다. 분류·키보드 이동·완료 상태 영속성·파일 저장/HTML 열기·A/B 선택 영속성·이미지 확대/닫기·기록/자료 추가·설정 label·유튜브 설명 접힘/펼침을 검증했다. `days`도 보고서로 인식해 두 메뉴가 선택되던 문제를 수정하고 한 메뉴만 선택되는지 확인했다.

이번 수정의 새 Android 설치본, 실제 폰 수신·잠금화면, 실제 개인 자료 AI 분석, 새로운 OAuth 승인은 이 UI 검증 범위에 포함하지 않았다.
